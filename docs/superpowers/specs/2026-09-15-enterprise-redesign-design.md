# 企业级重构设计：ProjectHub

日期：2026-09-15
状态：已获用户批准（分节确认）

## 1. 背景与目标

ProjectHub 是一个纯前端（Remix SPA + Dexie/IndexedDB）的项目管理系统演示项目。现有实现功能完整但交互不专业：首页即项目列表、无全局导航层级、缺少用户/权限/删除/更新的规范交互。

本次重构目标：

- 系统定位为**团队协作平台**（类 Worktile/Teambition），以项目为中心，首页为工作台
- 建立企业级信息架构：侧边栏 + 面包屑的全局 AppShell
- 补齐常规交互闭环：用户管理、权限矩阵、软删除回收站、操作审计、CRUD 反馈规范

实施策略为**方案 A：分层渐进重构**，分三个阶段，每阶段独立可验证（typecheck + 测试兜底）。

## 2. 信息架构与 AppShell

### 路由结构

```
/                           工作台（新首页）
/projects                   项目列表（从首页拆出）
/projects/:id/board         看板
/projects/:id/list          列表
/projects/:id/settings      项目设置（成员/角色/状态列/危险区）
/notifications              通知
/admin/users                用户管理（仅 admin）
/admin/audit                操作审计（仅 admin/projectAdmin）
/trash                      回收站
/settings                   个人设置（语言/备份/压测工具）
```

### AppShell 布局

所有页面共享的全局布局组件：

- **左侧边栏**（固定 240px，可折叠到 64px 图标模式）
  - 顶部：品牌 + 全局搜索入口（`/` 键聚焦，搜任务/项目，结果跳转）
  - 主导航：工作台、项目、通知（未读红点）、回收站
  - 底部：管理后台分组（用户/审计，按 RBAC 显隐）+ 当前用户卡片（头像/名字/角色；点击弹出切换用户与个人设置入口）
- **顶栏**：面包屑（如 `项目 / 网站改版 / 看板`）+ 上下文操作区（如项目页的"新建任务"）

### 上下级页面关联机制

- 侧栏当前项高亮
- 面包屑每级可点击返回；层级：工作台 > 项目列表 > 具体项目 > 当前视图
- 任务详情保持为对话框（非路由），通过 URL hash `#task=xxx` 支持深链与刷新还原

## 3. 数据层设计

### 模型变更（Zod schema 同步升级）

- `Task` / `Project` / `Comment` 增加 `deletedAt: string | null`
- `Task` 增加辅助字段 `deletedByProjectId: string | null`（区分独立删除 vs 随项目级联删除）
- 新表 `auditLogs`：`{ id, actorId, action, entityType, entityId, summary, createdAt }`；action 枚举：`create / update / delete / restore / purge`
- Dexie 升级到 schema version 2，迁移脚本为存量数据补 `deletedAt: null`

### 查询规则（repository 层）

- 列表查询默认过滤 `deletedAt === null`；回收站页显式查询 `deletedAt !== null`
- 启动时清扫任务：`deletedAt` 超 30 天的条目永久删除（记 `purge` 审计）

### 写操作规则（service 层）

统一四步、一个事务边界：RBAC 检查 → 写库 → 写审计日志 → broadcast 跨标签页通知。

- 更新操作带 `version` 乐观锁：提交时 version 不匹配则提示"内容已被他人修改，请刷新"
- 删除 = 置 `deletedAt`；恢复 = 清空
- 项目软删时级联软删其任务/评论；仅独立删除（`deletedByProjectId === null`）的子条目可单独恢复；项目恢复时级联恢复

### 权限矩阵

| 操作 | admin | projectAdmin | member | guest |
|---|---|---|---|---|
| 用户增删改 | ✓ | – | – | – |
| 项目创建/删除 | ✓ | ✓（仅自己管理的） | – | – |
| 成员/角色管理 | ✓ | ✓ | – | – |
| 任务增删改 | ✓ | ✓ | ✓ | – |
| 评论增删 | ✓ | ✓ | ✓（仅自己的） | – |
| 查看 | ✓ | ✓ | ✓ | ✓ |

## 4. 工作台首页（`/`）

定位：回答"我今天该做什么、我的团队在干什么"。

- **欢迎区**：按时段问候 + 当前用户 + 日期；两个数字胶囊：今日到期、已逾期
- **我的任务区（主体）**，分组标签页：
  - `待处理`（assignee 是我、未完成）/ `今日到期` / `已逾期` / `最近更新`
  - 每行：优先级点 + 标题 + 所属项目（可点击跳转）+ 截止日（逾期红色）+ 状态徽章；点击打开任务对话框
  - 空状态：提示 + "去项目列表创建"按钮
- **右侧栏（约 320px）**：
  - 动态流：最近 20 条审计日志，可点击跳到对应实体
  - 我的项目快捷卡片：名字 + 进行中任务数，点击直达看板
- 侧栏通知红点：liveQuery 订阅 notifications 表

数据来源：tasks 按 assignee 过滤、auditLogs、projects；新增 `workbenchService.load(userId)` 聚合查询。

## 5. CRUD 交互规范

### 创建

- 模态对话框表单；必填：任务标题、项目名
- 校验：失焦触发；标题非空、≤200 字符；错误显示在字段下方（红字+图标），`aria-live` 播报
- 提交中按钮 loading + 禁用
- Esc 取消；有未保存内容时弹"放弃修改？"确认

### 更新

- 行内可编辑（标题/状态/优先级/指派/截止日），写库后 liveQuery 自动刷新
- 对话框内富文本描述防抖 800ms 自动保存，顶栏显示"已保存"
- 乐观锁冲突：alert 提示 + "加载最新 / 覆盖"两个选择

### 删除

- 任务/评论：危险按钮 → 确认对话框（说明去向回收站、30 天清理）→ toast「已删除 · 撤销」（10 秒可恢复）
- 项目：项目设置页底部危险区，需**输入项目名称**才能删除
- 列表页批量：多选 → 浮现工具条"删除所选 (n)"，走确认 + undo

### 通用反馈

- 异步操作均有 toast：成功 3 秒自动消失；失败手动关闭、含重试按钮
- 空状态与加载骨架屏（替代"加载中…"文字）
- 键盘：`/` 聚焦搜索、`Esc` 关对话框、表格方向键导航

## 6. 管理后台与回收站

### 用户管理 `/admin/users`（仅 admin）

表格：头像、姓名、邮箱、全局角色、创建时间、状态。操作：新建（姓名+邮箱+头像色）、编辑、停用（停用后不出现在指派/提及列表，数据保留）。无密码概念；当前用户切换保留在用户卡片。

### 项目设置 `/projects/:id/settings`

- Tab 1 基本信息：改名/描述
- Tab 2 成员与角色：行内下拉改角色，移除成员需确认
- Tab 3 状态列：增删改、拖拽排序（复用 fractional index）
- Tab 4 危险区：删除项目（输入名称确认）

### 操作审计 `/admin/audit`

时间线表格：时间、操作者、动作徽章（创建绿/更新蓝/删除红/恢复青）、对象摘要。筛选：操作者/动作/实体类型；分页每页 50。

### 回收站 `/trash`

- Tab 分项目/任务/评论；每行显示删除时间、剩余保留天数（进度条）
- 操作：恢复、立即永久删除（admin，强确认）
- 顶部提示"条目保留 30 天后自动清除"

## 7. 测试策略

- 单元：soft-delete 过滤、乐观锁冲突、级联删除/恢复、RBAC 矩阵全组合、审计写入
- 组件：表单校验、undo toast 时序
- 现有 24 个测试保留适配（repository 查询签名变化处改断言）

## 8. 实施阶段

1. **阶段一**：AppShell + 路由重排 + 工作台首页
2. **阶段二**：数据层（软删/审计/乐观锁）+ 回收站
3. **阶段三**：管理后台 + 项目设置 + CRUD 规范落地

每阶段结束跑 `tsc --noEmit` + `vitest run` + `remix vite:build` 验证。
