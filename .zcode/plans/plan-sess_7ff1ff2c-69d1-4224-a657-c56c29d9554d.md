# 权限模块重构计划（R1–R3）

## 现状问题（探索结论）

1. **非成员默认按 member 对待**（`?? "member"` 三处 fallback 不一致）→ 非成员实际拥有完整任务 CRUD；`task:read` 403 检查永远不可达
2. **projectAdmin ≈ admin**：权限矩阵仅差 `project:delete`，管理层级形同虚设
3. **`project:create` 是死权限**；项目创建无任何门槛
4. **删除项目 UI/服务不匹配**：projectAdmin 看到可用按钮 → 点击抛未捕获 PermissionError；撤销路径硬编码 `"admin"` 绕过检查
5. **设置页全部直写 `db.projects.update`**（基本信息/成员/列），仅靠 HTML disabled 保护，服务层无对应方法
6. **标签/里程碑/关联/任务模板/项目模板/自动化六个服务零鉴权**；TaskDrawer 里任何 task:update 者可创建项目标签
7. **无最后管理员保护、无自我角色修改保护**：projectAdmin 可自授 admin
8. **可见性语义三分**：ContextPanel 过滤成员、GlobalSearch 全量搜索、/projects 全量展示
9. **guest 评论框渲染但提交抛未处理 rejection**；看板乐观移动先于权限检查
10. 成员池仅 3 个种子用户，每次建演示项目重复生成同名用户；`session.roleIn()` 是死代码

## 已确认的设计决定

- **角色体系**：Worktile 四级 — `owner / admin / member / guest`
- **可见性**：私有制 — 非成员不可见（列表/搜索过滤，直达 URL 403）
- **任务粒度**：不区分归属，成员可操作项目内全部任务
- **成员来源**：成员页内联新建本地用户（不恢复全局用户管理页）

## 新权限矩阵

| 权限 | owner | admin | member | guest |
|---|---|---|---|---|
| project:delete（含恢复） | ✓ | | | |
| project:update（基本信息/列/自定义字段） | ✓ | ✓ | | |
| member:manage | ✓ | ✓（admin 级变更仅 owner） | | |
| label / milestone / automation / template:manage | ✓ | ✓ | | |
| task:create / update / delete | ✓ | ✓ | ✓ | |
| task:read | ✓ | ✓ | ✓ | ✓ |
| comment:create | ✓ | ✓ | ✓ | |

补充规则（服务层 guard）：改角色到 admin、移除/降级 admin、移交所有权 → 仅 owner；不能修改自己的角色；owner 由 `project.ownerId` 唯一标记，移交后原 owner 变 admin。`project:create` 权限删除（人人可建，创建者即 owner）。任务关联增删并入 `task:update`。

角色解析单一入口：`roleIn(project, userId)` → `ownerId === userId ? "owner" : memberRoles[userId] ?? null`；**null 即非成员**，消灭所有 `?? "member"` fallback。

## 实施阶段（每阶段 typecheck + tests + build，浏览器走查，分阶段 commit）

### R1 角色内核 + 数据迁移
- `app/auth/roles.ts`：新 RoleId（`owner|admin|member|guest`）+ 新矩阵；`app/lib/role-labels.ts` + locales 加 `roleOwner`（所有者/Owner）
- `app/models/project.ts`：`ownerId: z.string()`；`memberRoles` 收紧为 `z.record(z.enum(["admin","member","guest"]))`
- `app/repositories/db.ts` version(7) 升级：`projectAdmin`→`admin`；回填 `ownerId`（取首位 admin，无则首个 key）
- `app/auth/session.ts`：`roleIn` 重写为唯一解析入口（返回 `RoleId | null`）；`seedUsers` 按姓名去重修复重复种子
- `project.repository.ts` demo 种子：张三=owner（写 ownerId）、李四=member、王五=guest；`projectTemplate.service.instantiate` 写 `ownerId: actorId`
- 调用点收口：`_app.projects_.$projectId.tsx`（role null → 403 页面，使其真正可达）、`TaskDrawer.tsx`、`session.roleIn` 消费者统一
- 测试：矩阵测试 + 迁移回填测试；修复既有角色字符串引用

### R2 服务层统一收口（鉴权下沉）
- 新建 `app/services/project.service.ts`：`updateBasic / updateColumns / addMember / removeMember / setMemberRole / transferOwnership / remove`，内置全部 guard（自改角色拒绝、admin 级变更仅 owner、最后 owner 不可降级）
- 六个零鉴权服务补 assert：label / milestone / automation（引擎 apply 除外）/ taskTemplate / projectTemplate（instantiate 除外）/ taskLink（task:update）
- `task.service / comment.service / trash.service` 改为**内部解析角色**（删除调用方传 role 的参数，消灭硬编码 `"admin"` 绕过）
- 路由改走服务：settings 全部 handler（基本信息/成员/列）、table 自定义字段、timeline 里程碑开关、/projects 模板删除
- PermissionError 消息改走 i18n key（新增 `noPermission` toast 文案，zh/en）
- 测试：新增 `project.service.test.ts`（guard 全覆盖）；更新 task/comment/trash 既有测试签名

### R3 私有制可见性 + UI 权限修正
- 新 helper `isProjectVisible(project, userId)`：/projects 列表过滤、GlobalSearch 过滤（项目+任务）、工作台"我的任务"过滤；删除 `notMember` 死 key
- 成员页重做：owner 行显示"所有者"徽章（非下拉）；自己的行禁止改角色/移除；admin 只能设 member/guest，owner 可设全部 + 移交所有权入口；**内联新建用户**（输入姓名 → 建用户 + 加入为 member）
- danger zone 仅 owner 可见（修复 projectAdmin 点击报错）；成员页对所有成员只读可见（编辑仍按权限）
- guest 修正：评论输入框直接隐藏（CommentList 加 canComment）；看板 handleMove 先检查权限再乐观更新；TaskDrawer 标签"新建"行仅 label:manage、保存为模板仅 template:manage
- locales：新增成员管理/移交/新建用户等 key（zh/en）；清理未使用 key（noCreatePermission / noEditPermission / purgeForbidden / notMember）
- 浏览器走查矩阵：**四身份 × 关键场景**（非成员 403 与列表不可见、member 建任务可用但设置只读、guest 全只读且无评论框、owner 删除/移交）
